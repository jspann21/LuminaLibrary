## 2024-05-26 - Debouncing Search Inputs

**Learning:** Search inputs currently trigger state updates on every keystroke, which triggers queries to the database and re-renders in the frontend. This is particularly problematic in a local-first desktop app handling thousands of entries, as frequent SQLite calls block the backend thread and cause noticeable UI stutter on rapid typing. The frontend already utilizes `useDeferredValue` for queries `deferredQuery = useDeferredValue(query)`, which means React won't block the UI while rendering the list, but we still make an unnecessary number of IPC calls and backend database queries because `api.getLibraryBooks` is triggered too often. Actually, `useDeferredValue` defers the React render, but it doesn't debounce the API calls triggered by TanStack Query if the query key changes. Wait, if the query key uses `deferredQuery`, then `deferredQuery` only updates when React has time, but if the user types fast, `deferredQuery` still updates for almost every keystroke, just slightly delayed. Debouncing the actual input state or the query value is much more effective at reducing IPC overhead.

**Action:** Implement a custom `useDebounce` hook to debounce the query parameters before they are passed to the `useQuery` hooks. This maintains the immediate responsiveness of the controlled input fields while preventing a flood of IPC calls and backend queries.
