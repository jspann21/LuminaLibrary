## 2024-05-24 - N+1 Bottleneck in SQLite Pagination with Correlated Scalar Subqueries
**Learning:** When evaluating paginated endpoints that rely on correlated scalar subqueries (like `group_concat` and `COUNT()`), SQLite will evaluate these subqueries for all matching rows *before* applying `LIMIT`/`OFFSET` if they are placed directly in the main `SELECT` statement. This results in severe N+1 performance bottlenecks when evaluating thousands of books where only a small page is actually requested.
**Action:** Always wrap the core matching logic (including filtering and sorting) in a `WITH ... AS (...)` Common Table Expression (CTE) and apply the `LIMIT`/`OFFSET` on the CTE first. Then join the CTE back to the main table to perform the expensive correlated subqueries only on the limited results.
