## 2025-02-18 - Early Aggregation Subqueries in SQLite
**Learning:** In SQLite, queries that `JOIN` a base table with a one-to-many relationship and then use `GROUP BY` to count (like counting books for tags) can be very slow due to building and sorting a massive intermediate dataset. Correlated scalar subqueries (like `(SELECT COUNT(*) ...)`) can also be slow if the outer table is large and not heavily filtered.
**Action:** When counting relationships for an entire table (e.g., all tags), push the `GROUP BY` into a subquery/derived table *before* joining it to the main table (`JOIN (SELECT parent_id, COUNT(*) ... GROUP BY parent_id) tc ON tc.parent_id = ...`). This "early aggregation" pattern ensures grouping happens on the raw child rows (often leveraging an index directly) and drastically reduces the rows joined, resulting in significant (e.g., >2x) speedups on large datasets.
